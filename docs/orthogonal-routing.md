# 直交コネクタールーティング

## 責務分離

```text
DungeonDocument.connections
  → connectionGeometry（現在の部屋から端点・回転後の方向を計算）
  → routeConnection / ConnectionRouter
  → orthogonalRouter
  → ConnectionRoute.points（ワールド座標、グリッドセル単位）
  → ConnectionRenderer（ピクセル座標へ変換してSVG Pathを描画）
```

`Connection` と保存スキーマ `1.1.0` は変更しない。
経路の座標列、曲がり角、SVG Path、通路ピースをドキュメント・履歴・IndexedDB・JSONへ保存しない。
移動・回転・Undo / Redo・保存後の読込・JSONインポートの後は、現在の論理状態から経路を再計算する。

`connectionGeometry.ts` は既存の `getWorldConnectors` と `connectorPoint` を再利用し、端点と回転後の方向を返す。
位置だけ必要な既存呼び出し向けに `connectionEndpoints` も維持する。

`routing/connectionRouter.ts` は派生型 `RoutePoint` / `ConnectionRoute` とRouter関数の境界を定義する。
`routeConnection` の第3引数でRouterを差し替えられる。既定は `orthogonalRouter`。
参照先の部屋・コネクターがない場合は `null` を返して描画を省略する。
将来のRouterはこの境界を利用でき、Rendererに経路探索を追加する必要はない。

## 経路の選択

単純な方向・座標の分岐で決定し、探索や経路コスト計算は行わない。

- 対向かつ向かい合う接続口: 同じ軸上なら1本線、ずれていれば中央の折り曲げ軸を使ったZ字。
- 対向だが互いに外を向く接続口: 両方の接続口から外へ出し、出口同士を水平・垂直の経路でつなぐ。
- 同方向の接続口: 両方の外側に折り曲げ軸を置く。同じ軸上では垂直方向へ迂回し、往復が重ならないよう出口距離を調整する。
- 直角の接続口: 外向きの出発・外側からの到着が可能ならL字。それ以外は両方向の外側を通る折り返し経路。

出口・迂回距離の基準は `CONNECTOR_EXIT_GRID_CELLS = 1` に集約する。
単純なL字・Z字の折り曲げ位置は端点から直接決める。近接した同方向・同軸の接続口では、出口距離を端点間距離の半分以下に調整する。
ルーターはSVGのピクセルサイズやズーム値に依存しない。
重複点と同方向に続く同一直線上の点を除去し、ゼロ長の区間や即座のUターンを避ける。

描画用Pathとクリック判定用の透明な太いPathは同じ経路を使用する。
既存の選択色、隠し通路の破線、クリック・キーボード選択、削除操作を維持する。

## 検証

`npm test` に既存の接続テスト17件とルーティングテスト24件を含む。

- 全16方向の組み合わせを、正負の座標差・同一軸・近接・同一座標の13配置で検証する。
- 経路の始点・終点、水平／垂直だけの区間、外向き出発・外側からの到着、ゼロ長区間・即座のUターンがないことを検証する。
- 同じ入力から同じ経路が生成され、入力や保存モデルを変更しないことを確認する。
- 正方形・長方形・L字の0° / 90° / 180° / 270°の座標と方向を確認する。
- 上下・左右移動とUndo / Redoによる再計算、Routerの差し替え、不正参照の扱いを確認する。
- ドキュメント・履歴・JSON・IndexedDBに経路情報が入らず、保存・再読込・JSON往復で同じ経路を再生成できることを確認する。

ブラウザでの確認手順は [コネクターシステムMVP](connector-system.md#検証) を参照。
長方形・L字の全4回転、破線表示、移動、接続線選択・削除、Undo / Redo、保存・再読込を確認する。

## MVPの範囲

他の部屋・接続線を横切る経路を許容する。最短経路の保証は行わない。
障害物回避、交差回避、A*、Waypoint、手動ルーティング、通路幅を考慮した探索、通路アセット生成は今後の拡張とする。
